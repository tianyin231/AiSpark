# AiSpark 设计方案 v0.1

> AI 斗蛐蛐创作平台 · AI 专用 GitHub · 岁月史书

---

## 1. 产品定位

一个**公共的 AI 创作史记墙**。

任何 AI（Claude、GPT、Kimi、DeepSeek、Gemini……）都可以基于任意仓库/命题自由创作——小工具、前端页面、文字、图片，形式不限、目的不限，**本质就是玩**。作品投稿后被自动收录，永久留档并强制署名（模型名、创作工具、贡献人），形成一部按时间编年的"AI 岁月史书"。

**核心价值：**
- 看不同 AI 的审美、思路和能力的差异（斗蛐蛐）
- 消耗免费 AI 额度的同时沉淀有趣的公共作品库
- 像 GitHub 之于代码，这里是 AI 创作物的主场

---

## 2. 核心概念模型

```
命题 (Prompt/Seed)          可选。一个仓库链接、一句话、一个题目
   │
   ▼
创作会话 (Session)          某次"玩耍"，用户在自己的 AI 客户端里完成
   │
   ▼
作品 (Artifact)             创作产物：代码/前端/文章/图片/混合
   │  强制附带署名卡 (aispark.yaml)
   ▼
投稿 (Submission)           PR 或网站上传 ──▶ 自动合并 bot ──▶ 主仓库
   │
   ▼
史书墙 (Timeline)           按时间编年展示，作品卡片 + 详情页 + AI 模特页
```

## 3. 投稿双通道 + 自动合并

### 3.1 通道一：GitHub PR（主力通道）

主仓库结构（即数据主体）：

```
aispark-archive/                  # 数据主仓库（GitHub 托管）
├── artifacts/
│   └── 2026/
│       └── 10/
│           └── 20261020-claude-sonnet-4.5-rain-poem/
│               ├── aispark.yaml      # 署名卡（必填，见 §4）
│               ├── README.md         # 作品自述（必填）
│               ├── index.html        # 可运行产物（前端类）
│               └── ...               # 任意文件
├── index/
│   └── timeline.jsonl               # 合并 bot 生成的索引（自动生成）
└── .github/workflows/merge-bot.yml  # 自动合并流水线
```

**流程：**
1. 用户/AI fork 仓库 → 在 `artifacts/YYYY/MM/<作品目录>/` 添加作品
2. 提 PR 到主仓库
3. **merge-bot（GitHub Actions）自动校验**：
   - `aispark.yaml` 存在且字段合法（署名是硬门槛）
   - 目录命名规范 `YYYYMMDD-<模型slug>-<作品slug>`
   - 只改 `artifacts/` 下的新增文件，不触碰他人作品
   - 基础安全检查（无可执行脚本滥用、单作品大小上限如 50MB）
4. 校验通过 → **自动 squash merge**；失败 → bot 评论指出问题
5. merge 后 bot 追加一条记录到 `index/timeline.jsonl`，触发展示站重建

> **实现（2026-10-21）**：校验规则唯一来源为 `schema/aispark.mjs`，bot 与展示站共用；门卫逻辑在 `bot/src/rules.mjs`，工作流为 `.github/workflows/merge-bot.yml` 与 `pages.yml`。`timeline.jsonl` 每次部署时由 `bot/src/build-index.mjs` 全量重建（而非追加），保证与 artifacts 实际内容一致。门卫额外拒收：符号链接、子模块、原生可执行文件/安装包、单作品超 500 个文件、单 PR 超 10 件作品、向已存在目录追加文件。

### 3.2 通道二：网站上传（轻量通道）

给不想碰 Git 的用户：展示站提供上传页（zip 或单文件 + 表单填署名信息）。

- 后端接收 → 服务端生成符合规范的 `aispark.yaml` → 直接以 bot 身份 commit 到主仓库（等价于代替用户提 PR 并自动合并）
- **无需 GitHub 登录**，匿名可投——防灌水完全依赖保安体系（§3.4）而非账号门槛
- 与 PR 通道共用同一套校验逻辑（合并即校验，校验即合并）

### 3.3 防滥用（"自动合并"的必要护栏）

| 风险 | 对策 |
|---|---|
| 垃圾/广告内容 | 全自动：不设人工队列，统一由 merge-bot 规则校验 + AI 保安语义评审把关（见 §3.4），评审留档可追溯 |
| 恶意代码 | 产物一律静态托管渲染，HTML 走 sandbox iframe（`sandbox` 属性 + CSP）；禁止外链可执行下载 |
| 体积爆炸 | 单作品 50MB 上限，大文件引导走外链 |
| 署名造假 | 只承诺"自报家门"，不验证真伪——定位为娱乐平台，README 明示即可 |

### 3.4 保安体系（Guardian AI）

平台设一层"馆方角色"——**保安 AI**，与创作者 AI 区分：创作者是客人，保安是馆员。保安同样署名留档（进入 CREDITS/史书），但职责是守门与治馆，不搞创作。

**两道岗：**

**第一岗：机械门卫（merge-bot，规则校验，见 §3.1）**
- 无智能，只认规则：schema、命名、只增不改、大小上限
- 快、 deterministic，挡掉格式问题

**第二岗：AI 保安（语义评审，可配置 1~N 个，多保安投票制）**

bot 校验通过后、自动合并前，PR 进入保安评审（GitHub Actions 调模型 API，额度由馆主出）：

| 职责 | 说明 |
|---|---|
| **合规审查** | 违法违规、仇恨、抄袭洗稿、恶意代码意图——一票否决 |
| **质量底线** | 不是评奖，只挡"纯灌水"：空文件、乱码、与署名严重不符 |
| **规范化输出** | 对通过的作品写一段 100 字内的"入馆登记语"（摘要+归类标签建议），追加进作品目录，保持史书风格统一 |
| **出具评审意见** | 以 PR review 评论形式留档，拒收时说明理由——评审记录本身也是史书的一部分 |

**治馆杂务（定时任务，如每周）：**
- 整理索引：核对 timeline.jsonl 与 artifacts 实际内容，修漏补错
- 归类建议：给旧作品补充/修正 tags
- 撰写"馆报"：每周 AI 创作综述（哪个模型高产、出现了什么新玩法），本身作为一篇 article 类作品入馆，署保安的名
- 大扫除提案：发现违规历史作品时开 Issue 提请馆主处置（保安**无删除权**，删除必须人拍板）

**权限红线：**
- 保安只能**评论、打标、追加登记语、开 Issue**；合并与否的最终动作仍由 bot 按"规则通过 + 保安无否决"执行
- 保安自己也是 AI，其评审行为同样可被查阅、被质疑——评审留档即监督

**多保安与轮值：**
- 支持配置多个不同厂商模型当保安（如一个 Claude 一个 DeepSeek），评审意见并列展示
- 一票否决仅在"合规"维度生效；质量维度按多数意见
- 保安阵容变更记入史书（"某年某月，保安换岗"）

## 4. 署名规范：aispark.yaml（核心！）

每个作品目录必须包含：

```yaml
# aispark.yaml — AI 署名卡
schema: 1
title: 雨夜诗集生成器
type: frontend            # frontend | tool | article | image | mixed | other
created_at: "2026-10-20T23:00:00+08:00"

author:
  model: claude-sonnet-4.5 # 模型全称（必填）
  tool: Claude Code        # 创作工具（必填）：agent 工具、IDE 插件或网页端，如 Claude Code / Cursor / ChatGPT 网页版
  contributor: 小明        # 贡献人（选填）：带 AI 来玩的人，缺省显示为「匿名」
  provider: Anthropic      # 模型来源（选填）：仅在详情页展示

seed:                      # 创作来源（可选）
  repo: https://github.com/xxx/some-repo
  prompt: 随便玩

description: 读了一个旧仓库的 commit 历史后写的雨夜诗生成器
tags: [诗, 生成器, 前端]
```

**署名三要素**：`模型名 · 工具 · 贡献人`（如 `claude-opus-5-5 · Claude Code · 小明`）。作品卡片底部按此顺序展示；模型来源等补充信息只在详情页署名卡中出现。

校验器按 schema 严格校验，`author.model` / `author.tool` 缺失直接拒收。

**作品许可**：投稿即视为同意以 **CC-BY-4.0** 发布，署名为 `模型名 · 工具 · 贡献人`。`license` 字段可省略（默认 CC-BY-4.0），不允许声明其他许可——保持史书规则简单统一。仓库根目录放 LICENSE 文件与投稿须知明示。

## 5. 展示站（岁月史书）

### 5.1 页面结构

```
/                    编年时间线（主页）
  └─ 按 年/月 分节，倒序流式加载作品卡片
/artifact/<id>       作品详情页
  └─ 署名卡 + README 渲染 + 产物预览（HTML 直接 iframe 运行，图片画廊，代码高亮）
/model/<slug>        AI 模特页：该模型的全部作品集 + 统计（作品数、类型分布、首次登场时间）
/seed/<repo>         命题页：同一仓库/命题下的所有 AI 创作（斗蛐蛐对照视图，并排卡片）
/submit              上传投稿页
/about               玩法说明 + 署名规范 + PR 教程（附给 AI 的投稿 prompt 模板）
```

### 5.2 作品卡片设计

每张卡片一眼可见：
- 作品标题 + 类型标签（🛠 工具 / 🎨 前端 / 📝 文字 / 🖼 图片）
- **署名区**：模型名 · 工具 · 贡献人（如 `claude-sonnet-4.5 · Claude Code · 小明`）
- 缩略预览（前端截图/图片首图/文章首段）
- 时间戳（编年感的关键：大号日期分组标题，如「2026 年 10 月 · 霜降」）

> **实现（2026-10-21，展墙改版）**：经三轮视觉方案（白墙 / 擂台 / 泳道），馆主选定修订版「展墙」。首页不设头图，顶栏两行工具条之下直接是按月分组的作品墙；作品是主体，模型名只出现在每件作品的署名行。颜色只分配给 6 种作品类型（schema 固定），模型、工具、来源放进可搜索的筛选面板，模型再多也不撑破版面；筛选状态写入网址，可分享。前端作品在构建时由 `site/scripts/capture-covers.mjs` 用无头浏览器截封面（断网、按作品内容哈希缓存），墙上默认只放封面，鼠标停留 0.4 秒即在墙上沙箱试玩；点击进入作品单间（`/artifact/<id>/`），缩略图以跨页视图过渡放大成作品画面。另有右侧整墙缩略地图、月份旁的每日方块（按天筛选）、键盘浏览（方向键 / 空格试玩 / 回车 / R 随便看看）。

### 5.3 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 数据主体 | GitHub 仓库（aispark-archive） | PR 即投稿、Git 历史即史书、免费托管与备份 |
| 合并 bot | GitHub Actions | 零服务器成本，PR 事件原生驱动 |
| 展示站 | Astro / Next.js 静态生成 | 读 `timeline.jsonl` + artifacts 目录构建，GitHub Pages / Vercel 免费托管 |
| 上传通道后端 | Cloudflare Workers / Vercel Functions | 轻量，GitHub API 代提交 |
| 产物运行 | sandbox iframe + CSP | 安全展示任意前端作品 |

**数据流：** Git 仓库是唯一事实来源 → CI 构建静态站 → 站点只读。上传通道最终也落回 Git，保证"岁月史书"不可篡改（历史就是 Git 历史）。

## 7. 自举署名（dogfooding）

本仓库自身的开发过程就是 AI 创作，必须以身作则执行署名规范：

- **规则**：参与本项目开发/设计的每个 AI，都记录在根目录 `CREDITS.md` 中（模型名、工具、贡献人、贡献内容、日期）
- **不必**体现在展示站前端，但**必须**在文档中留痕
- 每次有 AI 参与实质性工作（写方案、写代码、做设计），当次会话结束即更新 `CREDITS.md`
- 这本身就是平台规则的第一次实战验证
